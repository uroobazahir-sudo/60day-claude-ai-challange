Architecture Overview

Planner analyzes the bug report against the original code and produces a root-cause diagnosis and fix strategy — this seeds the Executor with direction instead of a blind first attempt.

Executor writes the first corrected draft of the Java code following the Planner's strategy.

Evaluator scores the current draft strictly on correctness (0–10) every round, using the original bug report, the draft, and full round history — this is the number the stop-check reads.

Critic receives the Evaluator's score and reasoning, and turns it into a specific, actionable critique — the bridge between "what's wrong" and "what to change."

Improver rewrites the draft using the Critic's priority fix, producing the next round's candidate.

Memory Manager compresses each round into a short note (what was tried, what worked) that's threaded into every future Evaluator/Improver call — this is how the pipeline avoids re-making the same mistake across rounds.

Safety Monitor runs once the loop exits, auditing the final draft for risks the correctness-only Evaluator wasn't scoring for (nulls, resource leaks, unsafe practices).

Final Reviewer gives executive sign-off: what was fixed, confidence level, residual risk, and the exact reason the loop stopped.

Stop-check governs flow by running after every Evaluator call, in fixed priority: plateau (two straight rounds under the delta threshold) → target threshold (score ≥ 9) → hard iteration cap (safety fallback, not the intended ending). Whichever fires first ends the loop and routes state to Safety Monitor → Final Reviewer instead of another Critic/Improver pass.

Extension Ideas

• Add a Test Generator agent that writes JUnit cases from the bug description, and have Evaluator run them programmatically instead of judging correctness by reading alone.

• Add a Style/Convention Critic as a parallel branch scoring readability separately from correctness, feeding a second axis into the stop-check.

• Let the Planner re-run if Critic flags that the original root-cause diagnosis was wrong, rather than only looping Evaluator→Critic→Improver.

• Persist Memory Manager notes across separate bug-fix sessions (localStorage/DB) so the pipeline learns a codebase's recurring pitfalls over time.
